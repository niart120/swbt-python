# 04. 実行状態、プロファイル、下位通信実装

## 責務の分割

`SwitchGamepad` は `async with`、生成、接続、終了、意味的な入力操作、`snapshot()`、`status()` を実装し、状態を持つ処理を `ControllerRuntime` へ委譲する。`PeriodicSwitchGamepad` は `apply()`、`DirectSwitchGamepad` は `send()` を送信方式ごとの公開操作として持つ。

`ControllerRuntime` は入力状態の保存、トレース出力、出力レポートの振り分け、接続処理、下位通信実装、周期送信型のレポートループを所有する。具象コントローラーはプロファイルと送信方式を選び、正規化済みの内部設定で実行状態を初期化する。

## プロファイルと下位通信実装

プロファイルはコントローラー形状、デバイス名、HID レポート記述子、SDP 方針、ボタンのビット配置、スティック対応範囲、既定のレポート送信周期、色の既定値を定義する内部のプロトコル上の定義である。利用者は具象コントローラーを選び、プロファイルを直接差し替えない。

通常経路では実行状態が `create_default_transport()` を使って Bumble の下位通信実装を作る。Bumble の読み込みはその関数内に閉じ込め、`import swbt` では発生させない。

下位通信実装の差し替えは `tests/gamepad_factory.py` だけが所有する。テスト補助は `ControllerRuntime` のコンストラクターを擬似通信実装を受け取るものへ一時的に差し替え、公開コンストラクターで作成したコントローラーを返す。配布パッケージにテスト専用の生成処理、公開 `transport` 引数、コンストラクターを介さない生成は追加しない。

## 維持する振る舞い

- Pro Controller と Joy-Con L/R の入力レポートの固定期待値テストを維持する。
- Joy-Con L/R の非対応入力は `UnsupportedInputError` とする。
- `InputReportBuilder` はコントローラー形状の分岐ではなくプロファイルの振る舞いに依存する。
- Bluetooth 機器なしで単体テストを実行できる。
- `swbt` モジュール直下はプロファイル型や下位通信実装の型を公開しない。
